## 数据源现实与降级

探测本机网络（curl 与 Node fetch 都试过）的结果：

| 接口 | 结果 | 处理 |
| --- | --- | --- |
| `qt.gtimg.cn`（腾讯行情） | 可用 | 主源 |
| `hq.sinajs.cn`（新浪） | 可用 | 备源 1 |
| `proxy.finance.qq.com`（K线/分时/分钟K） | 可用 | 主源 |
| `web.ifzq.gtimg.cn/appstock/app/day/query` | 可用，5 日 | 多日分时 |
| `push2.eastmoney.com/.../ulist.np/get` | 时通时断 | 备源 2，30s 冷却 |
| `searchapi.eastmoney.com/api/suggest/get` | 可用 | 搜索 |
| `push2his.eastmoney.com/.../kline|trends2` | 服务端直接断连 | 历史备源，失败后 5 分钟冷却 |
| 美股分时（腾讯 minute/query） | 只回 1 个点 | 客户端显示"美股暂无分时" |
| 港股五档（腾讯） | 全 0 | 不显示盘口 |

因此 P2.11 只落地了真正可用的部分：批量行情（含港股/美股）与搜索。东财 K 线/分时保持
实现但带健康冷却——换网络环境可能就有用，同时不会拖慢主路径。

## 刻意不吸收的

参考集里这几块能力很强，但会把"输入框下方的行情条"撑成第二个 `dsh-stock-bar`：

- AI 复盘 / 追问 / 自动跟踪（NoCandles）：模型额度、NDJSON 流、数据包维护都是长期成本。
  需要 AI 时用插件注册的 `stock_quote` 工具，让 agent 走自己的对话链路。
- 基金研报流水线（PerryLink）：与行情条定位无关。
- 9 个细分工具 + 57 接口目录（AnacondaKC）：工具太多会稀释模型的选择；一个批量
  行情工具够用。
- ETF 成分股、资金流、龙虎榜（NoCandles/AnacondaKC）：依赖东财 `push2his` / `F10`，
  在本机网络不可靠。
